### 文档成熟度图例
- 🟢 **运营层**:几乎每次工作都更新(任务/进度/未决问题流转)
- 🔵 **规格层**:产品规格,定稿后不轻易动,改动需要走决策流程
- 🟡 **历史层**:决策记录,只追加不修改,变更走"修订条款"形式
- 🟣 **元层**:描述项目本身的元信息(代码组织/对外介绍)
- ⚪ **工具层**:操作工具,频率不固定,实测后迭代

## 3. 我应该先读哪个? (按身份)

### 🤖 你是 agent(Claude Code / Cursor / Claude Desktop)
**必读顺序**:
1. `STATE.md` §-1 产品方向 ← 1 分钟,知道现在在做什么模块
2. `STATE.md` §3 任务队列 ← 找一条待领取的任务
3. 任务里指定的 PRD 章节 ← 读规格
4. 干活
5. 收工时按 `STATE.md` 附录模板输出更新

**绝对不要**:跳过 STATE 直接读 PRD 然后开始假设。STATE 里有 PRD 没有的"今天的状态"和"未决冲突"。

### 👤 你是 Huan(项目主理人)
- **本周做什么** → `STATE.md` §3
- **某条决策为什么这么定** → `DECISIONS.md`(按日期搜)
- **想改一件事不知道改哪几处** → 本文 §4(下面那张表)

### 🤝 你是新协作者(未来加入的人)
**推荐顺序**:仓库根 `README.md`(项目是什么)→ `docs/README.md`(本文) → `STATE.md` §-1(当前定位) → `PRD.md` + `PRD-mentors.md`(模块规格) → `DECISIONS.md`(为什么这么定)

跳过 `MENTOR-PERPLEXITY-PROMPTS.md` 直到你真的要标注导师才看。

## 4. 改一件事要改哪些文档(速查表)

> ⭐ **这是本文档最值钱的部分**。下次你犹豫"这个改动该写在哪",直接查这里。

| 我要改的事 | 主改文档 | 同步改 | 备注 |
|---|---|---|---|
| **新决策(任何拍板的事)** | `DECISIONS.md`(追加新条目) | 若涉及具体规格 → PRD/PRD-mentors 对应章节<br>若涉及产品方向级别 → STATE.md §-1 | DECISIONS 永远只追加,旧条款用"修订:..."形式覆盖 |
| **模块 A 功能规格变更** | `PRD.md` | DECISIONS.md(写为何改)<br>STATE.md §3(若引发新任务) | 提升 PRD 版本号 |
| **模块 B 功能规格变更** | `PRD-mentors.md` | 同上 | 提升 PRD-mentors 版本号 |
| **当前进度 / 完成任务 / 进行中** | `STATE.md` §3 | (无) | agent 收工时主要更新这里 |
| **新出现的未决问题** | `STATE.md` §4 加 ❓ | (无,问题收敛后再走 DECISIONS 流程) | 问题决策化时:STATE §4 标记 ✅,DECISIONS.md 追加 |
| **产品方向变更(新增/砍掉/重定位 一个模块)** | `STATE.md` §-1 | PRD/PRD-mentors 大改<br>DECISIONS.md 追加变更原因 | 这是最重的变更,务必走完三处 |
| **Perplexity 提示词翻车修正** | `MENTOR-PERPLEXITY-PROMPTS.md` §6 迭代记录 + 主提示词本体 | (无) | 自迭代,不影响 PRD |
| **代码目录结构变更** | `PROJECT_STRUCTURE.md` | (无) | 实质改动后做,小调整不必 |
| **对外宣传文案变更** | 仓库根 `README.md`(不是本文件) | (无) | portfolio 用途为主 |

### 几个判断原则

**判断"是不是新决策"**:这个改动,3 个月后的我会想知道当时为什么这么定吗?是 → 追加 DECISIONS;否则 → 只动 PRD/STATE 即可。

**判断"是不是产品方向级"**:这个改动会让"模块 A / 模块 B 是什么"的回答变化吗?是 → 走 §-1;否则 → 只走 PRD。

**判断"要不要先写 STATE 的 ❓"**:遇到模糊问题不知道怎么定 → 先写 ❓ 挂在 STATE §4,不要硬往 DECISIONS 里写。决策化(明确答案)之后才进 DECISIONS。

## 5. 文档间冲突时谁赢?

按这个优先级:

```
DECISIONS.md  >  PRD/PRD-mentors  >  STATE.md  >  README/docs README
   ↑               ↑                    ↑              ↑
   决策              规格                  当前状态        门面/导航
```

**说明**:
- DECISIONS 是宪法,凡 STATE 或 PRD 与它冲突 → 改 STATE/PRD,不改 DECISIONS
- PRD 是当前规格,凡 STATE 或 README 与它冲突 → 改后两者
- STATE 反映"今天的现实",但不能反过来覆盖规格——若 STATE 显示规格做不到,要么改规格(走 DECISIONS 修订),要么改 STATE 任务

**例子**(就是这个项目刚发生过的):
- 4 月 27 号 DECISIONS 说"不建分类树"
- 5 月 1 号 STATE §B 实际改成了"学校→研究科→专攻"嵌套结构
- **冲突**:STATE 不能单方面赢;必须在 DECISIONS 加一条修订条款,把 4 月 27 号那条作废

## 6. 文档维护节奏

| 文档 | 期望节奏 |
|---|---|
| `STATE.md` | 每次 agent 收工(高频)+ 每次决策化(中频) |

| `MENTOR-PERPLEXITY-PROMPTS.md` | 实测翻车后立即记录(用时迭代) |
| 根 `README.md` | 大版本上线时(低频) |
| 本文 `docs/README.md` | 新增文档/废弃文档时(低频) |
